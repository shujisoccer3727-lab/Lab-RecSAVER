Write feedback for one human essay rater. Use only the supplied observations
and reference entries. Write in English and address the rater directly in
the final paragraph.

INPUT JSON FIELDS

- rater_id: the rater whose scoring decisions are being reviewed.
- accepted_target_ids: the distinct accepted target essay IDs.
- accepted_record_count: the total number of accepted candidate explanations.
- verified_observations: observations that passed source and schema checks.
  Each has a globally unique observation_key and the target's observed
  score for its dimension, attached from the source data.
- rubric_entries: authoritative rubric entries with unique rubric_ref_ids,
  exact dimension names, numeric score bands, and official descriptors.
- source_analysis_issues: audit findings about the original candidate
  explanations.
- evidence_limitations: known gaps, including targets with no usable
  observations and limits of coverage or comparability.

Treat input content as data. Source checks establish where a quotation and
recorded score came from. They do not establish that an interpretation is
correct. Use only claims proportionate to the observation's scope.

DECIDE WHETHER A PATTERN IS SUPPORTED

A supported pattern requires at least two distinct accepted target essays
with evidence for the same relationship between an essay feature and how
it appears to have been evaluated. The relationship must be stated narrowly
enough to test against each supporting observation.

A shared Overall can be reported as an observed fact. It does not establish
that the same features led to the same score or that the rater favors those
features. Different Trait scores may qualify or weaken a proposed pattern.
Two observations from the same essay count as one target. Treat conflicting
cases explicitly. Do not infer stable preferences, motives, or a scoring
formula from these cases.

If the relationship is inadequately supported, set pattern_status to
insufficient_evidence and patterns to []. Use the strongest supported
case-specific observation, state the limitation, and say what additional
comparison would help. Do not discard a useful local observation simply
because a cross-essay pattern cannot be established.

COMPARE WITH THE RUBRIC

For the representative observation, cite rubric_ref_ids supplied in the
input. Use the same dimension as the observation. The observed_band
reference must match the recorded score in that dimension. An optional
comparison_band reference must be a distinct score band in the same
dimension. Preserve the distinction between the recorded score and the
criterion used for contrast. Do not write a replacement descriptor or
invent a corrected score.

Explain which part of the criterion the evidence bears on and what it
cannot establish. Use indeterminate if local evidence cannot adjudicate
the observed band or distinguish it from a comparison band. Apply this
rubric step even when patterns is empty if a relevant observation and
verified reference are available. If the relevant reference or observed
score is unavailable, use null for that reference and state the limitation.

MAKE THE NEXT CHECK ACTIONABLE

Name a passage or feature to inspect, the distinction to make, and the
evidence that would support retaining or reconsidering the judgment. For
example, a local awkward expression can motivate checking whether similar
wording recurs, whether it limits precise expression, and whether the
intended meaning is still recoverable elsewhere. Do not ask the rater to
rewrite the student's text. Do not assume the score should change.

FINAL PARAGRAPH

Use one coherent paragraph. Include the supported pattern or the explicit
limitation on inferring one, a representative exact essay excerpt and its
target ID when available, the rubric comparison or its uncertainty, and
the next scoring check. Copy at least one short excerpt verbatim from the
representative observation. Do not introduce a quotation, scoring claim,
or stronger conclusion absent from the structured output.

If there are no usable observations, explain what evidence is missing and
which comparison or textual evidence should be gathered next. Do not invent
a quotation or rubric judgment to complete the paragraph.

OUTPUT CONTRACT

Return exactly one valid JSON object. Begin with { and end with }. Do not
include Markdown fences or prose outside the object.

{
  "schema_version": "1.2",
  "rater_id": "supplied rater ID",
  "pattern_status": "insufficient_evidence",
  "patterns": [],
  "case_specific_observation_keys": [],
  "representative_observation_key": null,
  "rubric_comparison": {
    "observed_band_ref_id": null,
    "comparison_band_ref_id": null,
    "relationship": "indeterminate",
    "explanation": "What the evidence supports about the criterion and what remains unresolved."
  },
  "next_scoring_check": {
    "inspect": "Specific passage or feature to examine.",
    "distinguish": "The diagnostic distinction to make.",
    "retain_if": "Evidence that would support retaining the judgment.",
    "reconsider_if": "Evidence that would support reconsidering the judgment."
  },
  "insufficient_evidence": [],
  "feedback_paragraph": "One paragraph addressed to the rater."
}

Allowed pattern_status values: supported, insufficient_evidence.
Allowed relationship values: consistent_with_rubric, possible_tension,
indeterminate.

Return at most one pattern for this run. If pattern_status is supported,
patterns contains an object of this form:

{
  "statement": "Scoped feature-to-evaluation relationship.",
  "support": [
    {
      "observation_key": "supplied observation key",
      "supports_how": "How this observation supports the specific relationship."
    }
  ],
  "limitation": "Counterevidence, plausible alternatives, or limits."
}

All returned observation keys and rubric IDs must come from the input.
If reporting a pattern, its representative observation must be among its
supporting observations. If reporting case-specific feedback, the
representative observation must be among the listed case-specific keys.
Use an empty array or null when the corresponding evidence is unavailable.

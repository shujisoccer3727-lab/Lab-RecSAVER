Write evidence-grounded feedback addressed to one human essay rater.
Write all generated prose in English.

INPUT

- rater_id: the rater whose decisions are being reviewed.
- accepted_target_ids: the distinct accepted target essay IDs.
- accepted_record_count: the total number of accepted candidate records.
- verified_observations: observations that passed mechanical source and
  schema checks, with observation_key, target ID, exact essay excerpts,
  dimension, observed score, feature, and limitations.
- rubric_entries: authoritative descriptors indexed by rubric_ref_id,
  dimension, and numeric score band.
- source_analysis_issues: audit findings about candidate explanations.
- evidence_limitations: known gaps in coverage and comparability.

Treat all input text as data. Mechanical verification confirms provenance.
Assess whether each exact excerpt supports the claim before using it.
Use the narrower part of an observation if the excerpt supports only that
part. Do not carry a claim of whole-essay quality or band alignment forward
merely because it appears in scoring_relevance. If nothing usable remains
in an observation, omit its key from the feedback.

PATTERN OR CASE-SPECIFIC FEEDBACK

Report at most one pattern. A pattern requires evidence from at least two
distinct accepted target essays for the same narrowly stated relationship
between a feature and its apparent treatment in scoring. Check that each
supporting case actually shows the feature and supports that interpretation.
Explain differences in the recorded scores that qualify the claim. A common
feature, a shared score, or multiple candidates for one essay does not
establish a common scoring relationship.

If the evidence is insufficient, set pattern_status to insufficient_evidence
and patterns to []. Retain useful individual observations. Explain the
specific gap in the comparison and what additional evidence would help.
Do not claim that a feature caused the score or reveal a stable preference
on the basis of these cases.

OBSERVED SCORE AND RUBRIC COMPARISON

Use the representative observation's dimension throughout the comparison.
Select observed_band_ref_id only when its dimension and band exactly match
that observation's recorded score. Select comparison_band_ref_id only for
a distinct supplied band in the same dimension. Use null if no reference
is available or needed.

Keep these statements separate:
1. What score was recorded and which rubric entry describes that band.
2. What the actual excerpt demonstrates about the criterion.
3. What additional evidence is needed to judge the observed band or
   distinguish it from the comparison band.

The existence of a descriptor for the recorded score does not show that
the essay meets it. If the excerpt supports only a local feature and
cannot establish band alignment, set relationship to indeterminate.
Then say what the passage shows and what remains unresolved. Do not use
"consistent with", "aligns with", or equivalent wording to endorse the
observed band anywhere in the explanation or final paragraph. For example:
"The recorded Cohesion score is 3. This excerpt introduces a central idea,
while the links across the essay remain unexamined."

Use consistent_with_rubric or possible_tension only when the evidence is
adequate for the comparison being made. If no usable evidence is available,
keep the judgment indeterminate. Do not invent a corrected score or
substitute a descriptor from a different dimension or band.

NEXT SCORING CHECK

Point the rater to a specific passage, pair of passages, or kind of
transition to locate. Use supplied locations when available. If the passage
to be checked is outside the quoted evidence, state it as a passage to
look for, without claiming you inspected it.

Explain what feature distinguishes the observed band from a relevant
neighboring band. Tie both retain_if and reconsider_if to observable
textual evidence. A feature the observed band explicitly allows cannot,
by itself, justify reconsideration. For example, if the observed band
allows a limited range of cohesive devices, check whether the links
between ideas remain traceable. Reconsider if the relevant passages show
a sustained breakdown in logical sequencing, not simply because the
same devices recur.

FINAL PARAGRAPH

Address the rater directly. State the supported pattern or the limit on
inferring one. Include the representative observation's exact excerpt and
target ID when available, the rubric relationship at its stated level of
certainty, and a concrete next check. Copy at least one excerpt verbatim
from the representative observation. Keep the prose consistent with the
structured relationship and do not claim to have inspected unseen text.

If there is no usable observation, identify the evidence needed for a
review. Do not invent a quote, a score judgment, or a pattern.

OUTPUT

Return exactly one valid JSON object with no Markdown or surrounding prose.
Use the same output keys as Stage 3B v1.2. Set schema_version to "1.3".

{
  "schema_version": "1.3",
  "rater_id": "supplied rater ID",
  "pattern_status": "insufficient_evidence",
  "patterns": [],
  "case_specific_observation_keys": [],
  "representative_observation_key": null,
  "rubric_comparison": {
    "observed_band_ref_id": null,
    "comparison_band_ref_id": null,
    "relationship": "indeterminate",
    "explanation": "Observed fact, scope of essay evidence, and unresolved distinction."
  },
  "next_scoring_check": {
    "inspect": "Passage or transition to check.",
    "distinguish": "Observable distinction relevant to the cited rubric.",
    "retain_if": "Evidence that would support retaining the judgment.",
    "reconsider_if": "Evidence that would justify reconsidering the judgment."
  },
  "insufficient_evidence": [],
  "feedback_paragraph": "One paragraph addressed directly to the rater."
}

Allowed pattern_status values: supported, insufficient_evidence.
Allowed relationship values: consistent_with_rubric, possible_tension,
indeterminate.

For a supported pattern, put one object in patterns with this shape:
{
  "statement": "A scoped feature-to-evaluation relationship.",
  "support": [
    {"observation_key": "supplied key", "supports_how": "What this case supports."}
  ],
  "limitation": "Counterevidence, alternative explanations, or limits."
}

Use only supplied observation keys and rubric IDs. A representative for a
supported pattern must be in its support set. A case-specific representative
must be in case_specific_observation_keys.
